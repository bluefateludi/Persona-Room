# 方舟互动展馆

让粉丝把角色素材组织成可互动、可收藏、可分享的个人展馆。

以《明日方舟》干员「黍」为首个示例，搭建一个集 **3D 角色模型、动态小人、角色文字与语音、主题家具和访客互动** 于一体的网页展馆。

用户可以进入展厅，观看手办、与小人互动、浏览角色档案、试听语音，也可以配置展品与家具，保存自己的展厅。项目的核心是完整、可复用的互动展馆体验；图片生成和 3D 建模是素材制作环节。

> 当前处于素材准备与产品设计阶段。以下功能是开发目标，不代表已经实现。黑客松首版按约 5 小时的开发窗口规划。

## 1. 产品由哪些部分组成

| 部分 | 展示内容 | 用户可以做什么 |
| --- | --- | --- |
| 3D 模型与文字 | 黍的彩色手办、名称、简介、展品说明 | 旋转、缩放、查看细节，打开对应说明 |
| 场景与动态小人 | 主题展厅、黍的 Spine 动画小人 | 点击小人、触发动作与台词、获得参观提示 |
| 展厅家具 | 展台、展柜、档案桌、语音台、画框和装饰 | 点击功能家具、切换展品，编辑家具摆放 |
| 角色档案与语音 | 立绘、档案章节、语音条目与字幕 | 阅读、试听、切换条目、收藏 |
| 展馆配置与复用 | 角色内容包、家具布局、互动绑定 | 替换角色、保存配置、重新打开或导入展厅 |

## 2. 3D 角色模型与对应文字

- 将黍的 GLB 手办放置在展厅中央的展示台上，包含材质与贴图。
- 展示台旁提供名称牌和简短角色介绍；点击后展开完整展品说明。
- 进入模型检视模式后，支持旋转、缩放和恢复默认视角。
- 文字与模型通过展品 ID 关联，切换展品时同步切换说明。
- 明确区分游戏原始档案、创作者撰写的展品介绍和 AI 生成内容，并记录素材来源。
- 模型加载时显示进度或占位图；失败时显示参考图和重试入口，明确标注当前为图片预览。

首个展品为「黍的数字手办」。用户已提供 [Hi3D 模型页面](https://www.hi3d.ai/3d-model/f0fd85ac4abc4919a0aeb776205c0b42)，首版优先复用此模型，不再安排重复生成。当前项目已存在 `assets/shu/shu-figurine.glb`，尚需通过实际渲染验证材质、尺寸、朝向与加载性能。模型展示页 URL 不能直接当作 GLB 文件地址。

## 3. 场景搭建与动态小人

展厅采用可浏览的 3D 空间，首版以固定观察点和镜头切换组织参观路线，保证用户能快速找到展品。

建议布局：

- **入口区**：展馆名称、欢迎说明、操作提示。
- **中央手办区**：3D 模型、展示底座、灯光与名称牌。
- **角色互动区**：黍的动态小人，提供互动和导览入口。
- **档案区**：档案桌或资料终端，展开角色文字。
- **语音区**：留声机或语音台，播放语音并显示字幕。
- **立绘区**：墙面画框，展示角色立绘和作品。

### 动态小人的实现边界

Ark-Models 提供的是 **2D Spine 骨骼动画**，与中央的 3D 手办是两个独立对象。小人用于动作反馈与陪伴，手办用于立体检视。

- 黍的模型目录包含 `.skel`、`.atlas` 和 `.png` 文件。
- 按仓库说明使用兼容 Spine 3.8 的运行时，并正确处理预乘透明度（PMA）。
- 可将 Spine 动画渲染为带透明通道的画面，放入 3D 场景中面向镜头的平面；实际兼容性和显示效果需要验证。
- 加载后读取真实动画列表，再配置待机、点击回应等动作，不预先假定模型具备某个动作。
- 小人不自带 AI；动作、语音、字幕和展馆事件由应用绑定。

## 4. 展厅家具

家具既负责布置空间，也作为内容与互动的入口。首版至少包含以下对象：

| 家具 | 对应内容 | 互动行为 |
| --- | --- | --- |
| 中央展示台 | 3D 手办与展品说明 | 点击进入模型检视模式 |
| 档案桌／资料终端 | 角色档案 | 点击打开档案面板并选择章节 |
| 语音台／留声机 | 语音列表 | 点击选择、播放或暂停语音 |
| 墙面画框 | 立绘或手办参考图 | 点击放大并查看图片说明 |
| 装饰家具 | 屏风、盆栽、座椅等 | 编辑模式下选择和调整位置 |

首版家具可用简单的 3D 几何体制作，并通过配色与材质统一风格。图片素材可以用于画框和装饰，但不将家具图片当作现成 3D 家具模型。

**家具需要立体形状，但不必逐件使用 AI 生成。** 房间、展台、桌子、画框、屏风优先由代码组合几何体；重复家具复用同一个组件或模型。仅在核心体验跑通且额度允许时，为具有明显主题特征的装饰生成独立模型。家具的点击区域与内容绑定独立于外观，后续替换模型不重写交互。

每件家具具有独立 ID、类型、位置、朝向、尺寸和内容绑定。访客模式用于参观，编辑模式用于调整布局，避免拖动家具与浏览操作相互冲突。

## 5. 客户／访客可互动的元素

交互需要有清晰的视觉反馈和可保存的结果。

| 操作 | 系统反馈 | 首版范围 |
| --- | --- | --- |
| 点击小人 | 触发可用动作，播放绑定语音并显示对应字幕 | 必做；音频来源需先验证 |
| 点击手办 | 镜头聚焦，打开模型操作与文字说明 | 必做 |
| 点击家具 | 高亮选中对象，打开对应内容面板 | 必做 |
| 选择语音 | 播放音频，切换字幕和播放状态 | 必做；新语音开始时停止上一条 |
| 阅读档案 | 切换章节，记录已读状态 | 必做 |
| 点击「了解她的故事」 | 展示角色精选档案，并提供前往文库继续阅读的链接 | 必做 |
| 收藏展品／语音 | 更新收藏状态，再次进入仍保留 | 首版轻量实现 |
| 调整家具 | 预览位置或朝向变化，保存布局 | 首版使用位置预设或数值控制 |
| 完成参观 | 根据浏览、阅读、试听记录显示参观进度 | 时间允许时加入 |

语音从用户点击后开始播放，提供暂停与静音入口。字幕展示整条语音对应的文本；逐字同步不列入首版要求。没有音频时明确显示“暂缺语音”，仍可阅读文本。

首版完整体验路径：

**进入展馆 → 点击黍的小人 → 听语音、看字幕 → 检视 3D 手办 → 了解她的故事 → 阅读精选档案／前往文库继续阅读 → 收藏内容 → 调整一件家具并保存 → 再次打开恢复状态。**

### 「了解她的故事」：角色介绍与文库阅读

- 在角色介绍面板和档案桌提供「了解她的故事」按钮。
- 点击后先在展馆内打开精选档案面板，展示角色简介、精选档案片段及对应章节标题和来源，帮助访客了解角色。
- 面板内提供「前往文库阅读」按钮，链接到 [泰拉文库](https://terra-library.pages.dev/)，在新标签页打开，保留当前展馆与参观进度。
- 如果已核验角色或相关故事的文库直达链接，优先使用该链接；尚未配置时使用用户提供的文库首页，并提示搜索角色名称「黍」。不猜测角色页面路径。
- 精选档案使用已核对的角色数据，由创作者选择展示片段；文库作为进一步阅读入口，首版不依赖抓取或嵌入外部页面。
- 每个角色独立配置精选档案和阅读链接，换角色时同步切换内容。

## 7. 复用方式

展馆程序与角色内容分离，以统一内容包关联素材和互动：

| 配置部分 | 包含内容 |
| --- | --- |
| 角色信息 | 角色 ID、名称、简介、头像、立绘 |
| 3D 展品 | 模型路径、封面图、文字说明、默认观察视角 |
| 动态小人 | Spine 文件路径、运行时版本、实际动画名称映射 |
| 档案 | 章节 ID、标题、正文、来源 |
| 故事阅读 | 精选档案条目、阅读按钮文案、文库链接、链接是否已核验、搜索提示用的角色名称 |
| 语音 | 条目 ID、标题、字幕、语言、音频路径 |
| 家具布局 | 家具类型、位置、朝向、尺寸、绑定的展品或内容 ID |
| 互动规则 | 点击对象、触发动作、播放语音、打开面板等事件绑定 |

新增干员时，导入新的内容包并配置动作、音频和展品映射，复用同一套展厅、播放器、档案面板和互动逻辑。缺失某类素材时，只对相应功能显示明确的缺失状态。

首版使用本地存储保存布局、收藏和阅读状态，支持导出／导入 JSON 配置。公开链接分享和跨设备同步作为后续功能，不能用本地保存冒充已发布分享。

## 8. 黑客松首版范围与验收

### 开发流程与节奏

按 ask-matt 的路由建议，本项目适合先冻结首版规格，对 GLB／Spine 等必须运行才能回答的问题做小验证，再按明确依赖拆分工作并集成验收。本节记录开发计划，尚未启动完整的技能工程流程或并行实现任务。

核心原则：**先用简单几何体打通完整交互，素材准备与开发并行，真实资产通过固定接口替换进场景。** 占位物仅用于开发；最终验收仍要求真实手办与动态小人，不将占位图视为功能完成。

以下时间从正式开工开始计算，是目标时间盒，不是对生成服务耗时的保证。

| 阶段 | 时间 | 并行推进的工作 | 阶段交付 |
| --- | --- | --- | --- |
| 0：约定接口、锁定素材 | 0–20 分钟 | 定义角色内容包、家具 ID、点击事件；登记现成模型和缺失素材 | 一份所有模块共用的数据约定与素材清单 |
| 1：尽早验证风险 | 20–60 分钟 | 素材线试载 GLB、Spine、音频；场景线搭房间和几何体家具；交互线用示例数据做档案与播放器 | 展厅能打开、家具可点击；明确实际素材的可用性 |
| 2：跑通完整参观 | 60–150 分钟 | 接入手办和小人；联动字幕、语音、精选档案及文库入口 | 用户完成一次“进馆—互动—阅读—试听”的真实体验 |
| 3：实现复用与布展 | 150–240 分钟 | 家具位置预设、收藏、布局保存、配置导入导出；统一视觉与镜头 | 换内容无需改核心逻辑，刷新后恢复布展结果 |
| 4：冻结与交付 | 240–300 分钟 | 停止增加功能和提交新生成；处理加载、音频和性能问题，准备发布与演示 | 可运行版本、完整演示路线和已知限制 |

### 三条并行工作线与依赖

| 工作线 | 负责内容 | 启动条件 | 提供给其他模块的结果 |
| --- | --- | --- | --- |
| A：素材与角色数据 | 现成 GLB、Spine、精选档案、语音与字幕映射 | 素材来源已知即可开始检查 | 整理后的角色内容包、可用文件与验证记录 |
| B：3D 场景与家具 | 房间、灯光、镜头、家具、模型检视 | 阶段 0 的 ID／尺寸／事件约定完成；不依赖最终模型 | 可交互场景、稳定的对象 ID 与点击事件 |
| C：面板与用户状态 | 角色介绍、语音、档案、收藏、配置保存 | 阶段 0 的内容结构约定完成；可用示例数据先开发 | 内容面板、播放控制与本地状态存储 |

- A、B、C 的第一批真实成果在第 60 分钟合流检查，随后每 30–45 分钟集成一次；避免最后一小时才首次合并。
- 单独指定集成负责人维护公共数据结构和入口文件；各工作线主要修改各自目录，接口变化先同步。
- 手办与家具进入固定容器，约定地面锚点、目标尺寸、朝向、缩放和点击范围；真实模型到位后替换容器内的显示对象。
- 语音采用条目 ID 绑定字幕；Spine 动作采用实际动画名称映射；素材缺失有显式状态。
- 如果启动多个执行代理，素材线统一持有生成任务的提交与查询职责，其他代理读取任务记录，避免重复调用 MCP。
- 第 60 分钟仍不可用的素材列为风险项，给出预计处理时间；第 150 分钟仍缺少的核心能力明确标注为未完成，并调整演示范围，不静默降低验收标准。

### 3D 资产获取策略

| 资产 | 首版获取方式 | 是否需要新生成 |
| --- | --- | --- |
| 黍手办 | 用户提供的 Hi3D 模型，导出并验证后接入 | 否 |
| 黍动态小人 | Ark-Models 的现有 Spine 文件 | 否 |
| 房间、展台、桌子、画框、屏风 | 代码构建立体几何与材质，可重复实例化 | 否 |
| 角色立绘与档案 | 已有素材与整理后的数据 | 否 |
| 特殊主题摆件 | 仅在确有必要时生成或选用可复用资产 | 可选，不阻塞核心开发 |

如果决定新增主题摆件，在开工初期完成参考图、报价和必要确认后提交任务，等待期间继续场景与交互开发；结果就绪再下载验证并替换。不要为了等待模型而停止其他工作。

### MCP 调用与额度管理

实际的调用次数限制、频率限制、并发任务上限和积分余额是不同约束，目前未确认具体配额，不假设查询免费就不受调用限制。

- **当前已确认只新增 1 件主题家具**：稻穗主题档案柜，采用 PNG 参考图 → Hi3D 报价 → 用户确认 → GLB 的流程。手办和 Spine 复用现有素材，其余家具由代码搭建。素材线统一管理生成，等待期间其他工作继续。
- 获取现成模型文件不应触发重新生成；如果 MCP 没有按模型页面读取的能力，使用页面提供的正常导出入口，不将模型页面 ID 猜作任务 ID。
- 对确需新增的资产，以“参考图集合＋生成参数”去重；同一方案只报价一次，每份报价只提交一次。收费 3D 生成遵守接口要求，在用户确认当前报价后提交。
- 保存素材来源、参数摘要、报价、任务 ID、任务状态、下次允许查询时间及已用调用数。提交结果不明确时先查原任务记录，不直接重试创建。
- 查询间隔不短于服务返回的 `next_poll_after`，并结合剩余额度安排；可在每次集成检查时查询已到期的任务，不用高频轮询等待动画。
- 按每个新增任务预留“上传（若需要）＋报价＋提交＋N 次查询＋结果获取”的调用预算；N 由实际配额确定，不预先承诺固定总次数。
- 在额度紧张时停止可选生成，保留核心结果获取所需的调用预算。任务失败或查询预算耗尽时记录状态，不自动购买重试。
- 验证后的资源存入项目资产目录，页面刷新、用户点击和现场演示均不触发 MCP。临时下载链接不作为长期运行依赖。

### 阶段取舍

优先保证真实手办检视、动态小人、至少一条语音与字幕、精选档案与文库跳转、功能家具点击。随后完成最小布展保存与配置导入导出，证明复用性。复杂自由漫游、拖拽编辑器、更多 AI 家具、自由聊天和跨设备同步留到后续。

第一轮技术验证前，5 小时能否全部完成仍有不确定性；首要风险已从“重新生成手办”转为“现成 GLB 加载、Spine 运行兼容、语音文件取得”。

### 验收标准

- [ ] 展厅中同时存在可检视的 3D 手办与可播放的 Spine 小人。
- [ ] 手办和展品都有对应文字，点击后能查看。
- [ ] 至少三类功能家具可点击，并打开正确内容。
- [ ] 点击小人能触发实际存在的动画，以及至少一条可播放语音和对应字幕。
- [ ] 档案章节可浏览，收藏或阅读状态可以保存。
- [ ] 点击「了解她的故事」可查看当前角色的精选档案；「前往文库阅读」在新标签页打开配置链接，原展馆状态保留。
- [ ] 至少一件家具的位置或朝向可以调整，并在刷新后恢复。
- [ ] 内容配置可导出、导入，替换内容时无需改动展馆核心逻辑。
- [ ] 缺少模型、音频或图片时，有明确提示且其余功能仍然可用。

后续扩展：多干员展馆、公开分享链接、完整家具编辑器、跨设备收藏、角色导览问答与参观任务。

### 首版前后端边界

| 层 | 负责什么 | 首版是否必需 |
| --- | --- | --- |
| 前端 | 3D 展厅、小人、语音、档案、布展、收藏和本地保存 | 必需 |
| 内容与导入脚本 | 从素材源整理角色内容包、校验引用、产出可部署文件 | 必需 |
| 公共数据定义 | 固定角色、家具、布局、事件与存档格式，含版本号 | 必需 |
| 在线后端 | 账号、跨设备同步、公开分享、后续服务端任务调度 | 当前首版不依赖；出现这些需求时启用 |

首版直接部署静态网页与精选素材，数据和存档通过统一读取／保存接口访问。后续接后端时替换这些接口的实现，3D 场景和内容面板不直接依赖 HTTP 请求或数据库。

后端目录为扩展边界，按需创建与实现；不为了目录完整而开发空接口。Codex 内可调用 MCP 不等于网页后端已获得同样的调用能力，后续在线生成功能必须单独验证服务接口、认证与配额。

### 素材发布规则

- `assets/` 保存来源文件；`content/` 引用需要发布的素材，记录来源与展示信息。
- 准备脚本仅将白名单素材和整理后的内容复制到 `frontend/public/content/`，不复制报价、任务令牌和完整生成记录。
- 内容中的素材地址使用部署后的相对路径，不写本机绝对路径或临时下载链接。
- GLB、Spine 和音频首次接入时完成验证，页面运行期间只读取静态文件，不调用生成 MCP。

### 并行开发的目录分工

- 素材线主要负责 `assets/`、`content/`、`scripts/` 和角色素材的加载验证。
- 场景线主要负责 `frontend/src/scene/`、`furniture/`、`character/`。
- 交互线主要负责 `frontend/src/features/`、`components/`、`state/`。
- 集成负责人维护 `shared/`、应用入口、内容读取接口、依赖版本和构建配置；公共接口变化同步后再修改。

本轮实际分工、接口与生成约定见 [并行开发规格](docs/parallel-development.md)，类型接口见 [公共契约](shared/src/contracts.ts)。任务拆分如下，三项均可立即启动，最终集成需要三项成果：

- [01 素材线](.scratch/gallery/issues/01-assets.md)：角色内容包、SpineActor 与主题家具，进度写入 `docs/status/assets.md`。
- [02 场景线](.scratch/gallery/issues/02-scene.md)：场景、工程入口、依赖管理与最终集成，进度写入 `docs/status/scene.md`。
- [03 交互线](.scratch/gallery/issues/03-interaction.md)：档案、语音、收藏、布局与配置保存，进度写入 `docs/status/interaction.md`。
